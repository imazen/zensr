# DSCF-SR evaluation

The [DSCF-SR repository](https://github.com/Yaozzz666/DSCF-SR) supplies a DSCF26
×4 reference implementation and a 535,137-byte checkpoint. Its code is MIT
licensed. The author also links [DSCLoRA on Hugging Face](https://huggingface.co/sssefe/DSCLoRA).

  `239e76bc4e4e738491c3963805c0a79f524400acf5fbde34b2cb1a855dd62cb1`.

  CUDA device selection; it does not modify the network's operations.

## Comparison protocol

Use the existing 697-input ×4 cohort: 17 source/category representatives,
zenjpeg q5–100 every five, 420/444, plus clean inputs. Preserve its HR reference,
CatmullRom degradation, no-border-shave RGB scoring and category × quality
breakdowns. Score SSIMULACRA2 and Butteraugli overall/p-norm-3; this does not
establish subjective preference or a fresh held-out result.

Retain every scored RGB8 upscaled output as lossless PNG with pixel and PNG
hashes. This includes native SPAN and CatmullRom controls. IQA maps stay off.
The previous external runs retain their real scores-only identities; fresh
retained-output runs regenerate those images and must match their earlier
pixel hashes and scalar scores before being described as recovered artifacts.

Measure codec-excluded CPU FP32 calls separately at LR 64/128/256, requested
threads 1/4, with three fresh processes and three timed calls per process.
Loading, warmup, codec/IQA and output archival stay outside the timer.
Preserve the existing CPU timing fixture bytes. This adds evaluation support;
a native product implementation or runtime default is not selected by this
protocol.

## Measured quality and CPU results

The complete [quality × category comparison](../../benchmarks/external_sr_models_2026-11-09.md)
includes all 697 DSCF inputs. Mean SSIM2 gain / observed harm / mean Butteraugli
p-norm-3 change against CatmullRom:

| Inputs | SSIM2 gain | Harm | Butteraugli change |
|---|---:|---:|---:|
| Clean | +12.147 | 0/17 | −1.374 |
| JPEG q5–20 | −1.504 | 83/136 | +0.505 |
| JPEG q25–60 | +0.073 | 141/272 | −0.123 |
| JPEG q65–100 | +6.119 | 20/272 | −0.976 |

Lower Butteraugli is better. These reused sources have one image per category;
the repeated JPEG encodings do not establish population harm rates. DSCF is a
promising clean/high-quality SR candidate, with a low-quality JPEG tradeoff.
No new default was adopted.

CPU: Intel Core Ultra 7 265K, verified P-core cpuset, batch 1, FP32, no BF16,
INT8 or torch.compile. All 72 invocations completed: six size/thread cases,
three fresh process blocks, three configurations plus native-SPAN A/A. Entries
are milliseconds, the median of three process means (three timed calls each).

| LR → HR | PyTorch 1 thread | PyTorch 4 threads | tract 1 thread | tract 4 threads | Native SPAN 4 threads |
|---|---:|---:|---:|---:|---:|
| 64 → 256 | 12.761 | 4.419 | 14.966 | 13.505 | 36.210 |
| 128 → 512 | 51.869 | 15.904 | 63.919 | 40.312 | 85.013 |
| 256 → 1024 | 212.271 | 69.368 | 265.800 | 117.968 | 253.008 |

Input tensors are in memory. Loading, ONNX optimization, warmup, codecs, IQA,
RNG reseeding and hashing are outside the timer. Actual inference and output
allocation remain inside. No overlapping sweep, verification or archive copy
ran during this CPU matrix. These are descriptive Iterate observations, not
a formal Confirm decision or a promoted performance baseline.

The exported ONNX graphs have fixed input sizes and one RGB output; the
author’s optional feature-output branch is fixed off. Tract retains one/four
thread raw-output identity for all three sizes. PyTorch raw outputs differ
across thread counts, while each setting repeats exactly in all three fresh
processes. CPU-versus-GPU perceptual quality and cross-backend pixel equivalence
are not certified. No native Rust DSCF kernel or production backend is added.
