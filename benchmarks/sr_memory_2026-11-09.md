# SR output storage and activation lifetimes at 8192 × 8192

The memory experiment keeps model computation in FP32. Completed native SPANF
tiles are stored as RGB8 or RGB16 instead of retaining a full float image.
DSCF drops unused feature tensors earlier, then optionally converts its final
output to RGB8. No streaming redesign or public product API is introduced.

All 12 fresh-process invocations completed, with two timed calls each. Every
compact result exactly matches its paired reference output. DSCF's float
hashes also match the previously recorded CPU and CUDA backend outputs before
any conversion. This is not a cross-backend equality claim.

## Measured CPU results

Core Ultra 7 265K, four threads, verified performance-core cpuset 0–7.
Latency includes inference and final conversion; RSS is measured whole-process
peak, including loading, warmup and verification.

| Model / output | Reference time (s) | Compact time (s) | Reference RSS (MiB) | Compact RSS (MiB) |
|---|---:|---:|---:|---:|
| Native SPANF / RGB8 | 5.812 | 6.278 | 1,053.1 | 376.7 |
| Native SPANF / RGB16 | 5.795 | 6.273 | 1,212.0 | 562.1 |
| PyTorch DSCF / float32 | 9.133 | 9.898 | 12,124.6 | 4,598.1 |
| PyTorch DSCF / RGB8 | 9.246 | 9.861 | 12,108.6 | 4,679.0 |

Native reference computes the full float image before integer conversion.
Compact uses the existing SPANF kernel on the same extended 128-pixel tiles,
crops the same 16-pixel halo, and converts each completed core directly into
the final integer buffer. The prototype reuses the existing public kernel
entry point per tile rather than adding a public output API. It incurs repeated
scratch setup and serializes final integer conversion under the output lock.
These are implementation differences, not profiled explanations of its timing.
The measured CPU tradeoff is lower memory with longer latency; defaults are
not promoted from these two-call observations.

Both native paths use digest-only validation without retaining multiple full
outputs. Consequently these matched references are lower than the original
[CPU size check](sr_8k_cpu_2026-11-09.md), whose verification held multiple
float images simultaneously. Do not attribute that harness difference to the
integer-output optimization.

## Measured CUDA results

RTX 4080, PyTorch 2.15.0+cu132, eager FP32, TF32 disabled, deterministic
algorithms, NCHW, batch one. No tiling or compilation in DSCF.

| DSCF output | Original time (ms) | Compact time (ms) | Original allocated VRAM (GiB) | Compact allocated VRAM (GiB) |
|---|---:|---:|---:|---:|
| float32 | 153.492 | 153.595 | 9.438 | 3.704 |
| RGB8 | 163.224 | 163.341 | 9.438 | 3.704 |

Peak reserved VRAM fell from **10.889 to 5.607 GiB** in both output modes.
These are PyTorch allocated/reserved high-water marks during timed inference;
driver/context allocations outside PyTorch are excluded. CUDA events are
synchronized. Output conversion is included; transfers are separate.

Compact DSCF's pinned device→host copy measured **42.039 ms for float32** and
**10.549 ms for RGB8**. RGB8 adds conversion cost while reducing final storage
and transfer volume. The frame's activation peak occurs before that conversion,
so RGB8 alone does not reduce peak inference VRAM in this experiment. Earlier
activation release supplies the VRAM reduction. These separate phases are not
an end-to-end pipeline benchmark.

DSCF reference and compact CPU RGB8 peaks also show that final conversion alone
does not guarantee a lower activation-dominated process peak. All DSCF warmups
validate a full float output, including the RGB8 cases.

## Output correctness and depth

Conversion happens only after the last model operation. The canon4→SR float
handoff remains outside this experiment: never quantize between those stages.
RGB8 matches the existing scored-image conversion: multiply by 255, add 0.5,
clamp to [0,255], then truncate. RGB16 uses 65535 and little-endian samples.
No transfer function or color-space conversion is introduced.

Native RGB8 and RGB16 are interleaved; the PyTorch final tensors remain planar
NCHW. Exact paired hashes compare the same layout and depth, not different
models or devices. Native tests cover saturation, rounding, odd/tiny edges,
one/three threads and padded input rows whose unused entries contain NaNs.
RGB8 also matches the pre-existing scored-image conversion helper.

RGB16 preserves more fractional output for subsequent editing; no improvement
in source accuracy or perceptual quality is established by this timing test.
Only native RGB16 is measured here. At this size an RGB8 output buffer is
192 MiB, RGB16 is 384 MiB and float32 is 768 MiB by layout; these are buffer
sizes, not predictions of process RSS. The prototype still retains the entire
integer output. It does not claim constant-memory streaming.
