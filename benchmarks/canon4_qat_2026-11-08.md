# Canon4 INT8 weight-only QAT — 2026-11-08

QAT recovered the mean SSIMULACRA2 loss from direct INT8 rounding and from
float fine-tuning followed by INT8 rounding on this cohort. It did not dominate
the original f16 model: all three QAT seeds increased observed harm frequency.
The f16 serving default is unchanged.

## Primary comparison

The frozen comparison contains **2,720 cells, 17 grouped origins and 17 content
strata**, four retained encoders (turbo, mozjpeg, jpegli, zenjpeg), 420/444, and
q5–q100 in steps of five. There is one metadata/hash-selected complete reference
per available content stratum. All selected IDs belong to the published
imazen-26 test bucket and are absent from the original 48,000-pair manifest;
publication origin groups seen in that manifest are excluded too. These are
previously inspected routing-study inputs, not a fresh corpus sample.

All arms use canon4's frozen default routing decisions, guard, deblock and
projection algorithms. Restoration coverage is **66.765%** on this designed
cohort, identical across arms. Absolute gain/harm values should not be compared
directly with the larger routing-study headline. Harm is loss versus plain
decode greater than 0.5 SSIM2 at identity scores ≤90, linearly tapering to 0.1
at 100, with strict decimal boundary comparisons.

Original f16's mean restoration gain is **+1.93967 SSIM2**. Across the three
QAT seeds, mean change versus f16 is **+0.00763**, with an exploratory paired
seed/origin bootstrap interval **[−0.00347, +0.02231]**. This interval includes
zero and is not a formal equivalence or population-risk guarantee.

QAT exceeds the matched untrained GPU-PTQ control by **+0.03304** on average
(interval **[+0.00398, +0.07086]**). It exceeds the three corresponding
float-fine-tune-then-PTQ controls by **+0.03946** (interval **[+0.01019,
+0.07788]**). That latter comparison is a disclosed secondary control using
already-frozen float checkpoints, with no optimizer steps or re-selection.
It supports an effect from quantization-aware adaptation beyond generic
fine-tuning followed by rounding on this cohort.

The additional loss versus f16 reaches **0.78996 SSIM2** with frozen routing.
Forced-repair diagnostics, which disable routing and the high-quality gate,
are also retained; their larger regressions are not hidden by the routed
summary. For example, seed 29's worst extra forced-repair loss is 1.54060 SSIM2.
The existing router was not recalibrated for these new models.

## Storage and execution

The original weight file is **86,406 bytes** of f16. Each QAT Q8PC model is
**45,408 bytes**, including its header and f32 channel scales, biases and
PReLU slopes. Lossless Zstandard level 3 gives **80,111 bytes** for the original
f16 file and **41,034 / 41,035 / 41,043 bytes** for QAT seeds 7/17/29.
Roundtrips restore every measured source byte.

These are **W8A32** models. The native evaluator reads actual packed INT8 data,
expands weights to f32 once, and uses the existing CPU convolutions. There is
no integer convolution speed or resident-memory claim. Q8PC is an experimental
model format, not a newly supported `.zensr` encoding or a serving-default change.

## Training and numerical controls

Three seeds (7, 17, 29) each run both float and QAT for 10,000 steps, with
identical batches, losses and schedules. Warm-start is the exact deployed
canon4 f16 SHA-256
`c3db9373791270bbe5493d3ee98cd4f62296510fe6931073e2966f433e9a5cf4`.
Fine-tuning uses 39,503 published-imazen-26-training-ID pairs, with 392
source-disjoint internal-validation pairs from the same published train bucket.
Inputs are retained mixed-encoder pairs; no JPEG generation was performed.
The baseline's inherited split exposure is not removed by this fine-tuning.

Compute is FP32 with AMP/TF32 off and deterministic algorithms. Batch is 16;
AdamW uses no weight decay, a 1e-5 ceiling, 250-step warmup and cosine decay to
2e-7. Loss is GT Charbonnier plus 0.25 times Charbonnier to frozen canon4.
Checkpoint selection uses internal-validation GT Charbonnier, not external IQA.
Selected QAT steps are **1,000 / 8,500 / 9,000**; selected float-control steps
are **5,500 / 3,500 / 7,500**. All six runs still completed all 10,000 steps.
The [protocol](../docs/CANON4_QAT.md) records the amendments and reproduction.

Native fake quantization and actual packed operands agree bit for bit. A test
caught division-versus-reciprocal rounding at one code before training; packing
now recovers native integer codes. A separate backend check found identical
initial CPU/GPU INT8 codes, but seven scale words differed (maximum expanded
operand difference 2.9802322387695312e-8). Both untrained controls were evaluated.
Their mean routed-score difference is +0.00010890 SSIM2 for GPU conversion.
Every repeated baseline row across both supplementary runs matched the original
scores and control fields exactly: **5,920 repeated rows**, without tolerance.

## Resolution evidence and scope

Two separate published-validation origins supply 240 retained zenjpeg cells
at 128/512/1024, with the same quality/subsampling grid and source exclusions.
Across seeds, routed mean change versus f16 is +0.01196 at 128, −0.00841 at
512, and −0.00135 at 1024. Only two origins support this secondary size check;
it does not establish full-resolution generalization. No harm event was
observed there under the existing curve; this is not a zero-risk guarantee.

Native loading, current adopted-model PyTorch goldens (unchanged 5e-4 ceiling),
packed-format rejection, source-boundary checks, and exact repeat/merge gates
pass. Full repair inference uses the existing CPU runtime. SSIMULACRA2,
Butteraugli max/pnorm3, exact RGB8 outputs and per-pixel Butteraugli maps are
retained for all arms. The earlier cancelled pixel-artifact audit was not resumed.
