## Timing and memory scope

Intel Core Ultra 7 265K; four requested threads; enforced performance-core
cpuset 0–7. Native SPANF uses its existing 128-pixel core tiles and 16-pixel
halos. FP32 arithmetic throughout; native SPANF expands its retained mixed f16
weights/f32 biases before timing. DSCF uses the pinned author FP32 checkpoint.
There is no native Rust DSCF implementation in this comparison.

Inputs are decoded planar RGB already in memory. Latency includes synchronous
inference, output/scratch allocation and existing native tiling. It excludes
model loading, tract planning, input reads, codecs, IQA, output hashing and
destruction. Tract's existing worker copies its output tensor into a Vec;
that copy remains included. JPEG repair is not included.

RSS is each fresh worker's `/usr/bin/time -v` maximum over its entire lifetime,
including loading, warmup, validation, hashing and timed calls. Validation
retains multiple full-resolution outputs simultaneously. These figures are
not isolated single-call activation peaks or minimum deployment requirements.
Native validation also checks exact equality against one-thread execution.
Every timed output matches its backend's repeated-output control; cross-backend
pixel equivalence and CPU-versus-GPU perceptual quality are not established.
All workers exited zero and reported zero swaps; the 16 GiB hard limit did not
fire.

## Protocol and limitations

The input repeats the earlier source-7109 decoded 128×128 timing fixture in a
16×16 grid, without interpolation. It is a periodic performance fixture, not
an additional quality sample or evidence of perceptual generalization to 8K.
All three backends receive identical bytes and validate 8192×8192 RGB output.
Input SHA-256:
`cc41343d9772fb4516d4db4f8f080417478ca01a09a618ac8534e789c832f6d6`.

The existing CPU workers run unchanged. The DSCF 256-pixel ONNX graph is
rebound to a 2048-pixel input fact by tract, which infers the convolutional
graph and validates the resulting 8192-pixel output. No new export is needed.

Zenbench Iterate ran one fresh-process block, two internal samples per backend,
without an A/A clone. Its order was PyTorch DSCF, tract DSCF, native SPANF.
Placement is verified, but boundary observations did not certify whole-host
cleanliness. This is an exploratory size check; it does not establish a
statistically confirmed ranking, optimized limit, or policy/default.
The earlier three-block report's requirements remain unchanged.

## Artifacts and reproduction

On i265: `/mnt/v/output/zensr/sr-8k-cpu-20261109/` holds the frozen input,
plan, asset identities, full stdout/stderr, packet, samples and progress.
Project NAS mirror: `output/zensr/sr-8k-cpu-20261109/`.
`ARCHIVE_VERIFIED-v1.json` records the packet digest and archive verification.
Prior model and worker artifacts remain in their existing mirrored study
directories. No IQA or diagnostic maps run. Outputs of this synthetic timing
fixture are hashed in RAM and released, as in the original CPU protocol.

Generate the plan with `just external-sr-8k-plan --sr-root <original-sr-root>
--dscf-root <original-dscf-root> --output <new-root>` and run the retained
zenbench binary's `pair <new-root>/plan.json --output <new-root>/run-v1` inside
the recorded P-core boundary and `run-heavy --mem 16G --jobs 4`. Both memory
scopes use MemoryMax=16G and MemorySwapMax=0. Then run
`just external-sr-8k-report <new-root>` to verify and summarize the evidence.
Use a new root for a new measurement; never pool additional calls into these
two-sample results.
