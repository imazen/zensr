# SR eval on the pinned clean split — 2026-08-03

Re-run of the imazen-26 super-resolution eval after `eval.rs` was given pinned
file selection and `gt_src` tracking. The headline is not the contamination fix:
it is that **the README's one reported loss is an artifact of an unpaired
statistic**, and that the model's genuine weak spot is a different subcorpus
that the README's statistic hides.

## Provenance

Harness `crates/zensr-bench/src/bin/eval.rs` at `4fc80c9`, host `lilith`.
Corpus `/mnt/v/imazen-26-clean`, selection pinned to
`eval_split/imazen26_eval_files.tsv` (8/8 found in all 8 subcorpora), all rows
`gt_src=png`. Protocol unchanged: center-crop HR (cap 512) → CatmullRom ×4 down
→ {spanf, lanczos, catmullrom} up → psnr / ssimulacra2 / butteraugli-n3 vs HR.
Compared against the committed `benchmarks/imazen26_eval_2026-07-22.tsv`.

## 1. The harness is exactly reproducible

The two runs share the same files (8/8 per subcorpus, 7/8 for `photos`). On the
five subcorpora whose references are native PNG, **every per-file psnr and ssim2
value is identical to two decimals**, and the subcorpus summaries differ by
exactly +0.00:

| subcorpus | reference | README-style Δ, 2026-07-22 | README-style Δ, 2026-08-03 |
|---|---|---|---|
| art-scans | native | +6.58 | +6.58 |
| documents | native | +26.99 | +26.99 |
| maps | native | +11.39 | +11.39 |
| photos | native | +4.76 | +4.76 |
| screen | native | +4.30 | +4.30 |

So pinning changed nothing for these — the earlier run happened to select the
same files. That is luck, not correctness: it held only because the listing had
not changed. It is now enforced.

## 2. Two statistics, and they disagree about which subcorpus loses

The README reports `median(spanf) − median(lanczos)`. That discards the pairing:
each image is compared against the *distribution* of the other method rather
than against itself. The paired statistic — median over files of
`spanf − lanczos` — is the one that answers "does this model help this image".

|---|---|---|---|---|
| documents | native | +26.99 | +26.86 | 1.00 |
| art-scans | native | +6.58 | **+12.63** | 0.88 |
| maps | native | +11.39 | +11.55 | 1.00 |
| textures | pristine3x | +4.34 | **+8.13** | 0.62 |
| screen | native | +4.30 | +6.69 | 0.75 |
| people | pristine3x | +8.73 | +6.38 | 1.00 |
| photos | native | +4.76 | +5.49 | 0.88 |
| renders | pristine3x | +5.93 | **−1.81** | **0.38** |

**`renders` is where the metrics disagree**, which the README's statistic hides

(Butteraugli: negative Δ is better.)

On `renders`, PSNR improves on **8 of 8** files and butteraugli on 7 of 8; only
ssim2 says the median image gets worse. So this is not a demonstrated
regression — it is a metric disagreement, and the interesting question is why
ssim2 dissents on synthetic content.

Per-file, `renders` is bimodal rather than uniformly bad: one file gains +20.05
ssim2 and another +6.37, while five lose 0.8–9.5. PSNR rises on every one of
them. A model that raises PSNR while lowering SSIM2 is the signature of
smoothing toward the pixel-wise mean at the cost of structure — worth looking at
the outputs directly before trusting either metric.

**Correction:** an earlier version of this file claimed butteraugli confirmed
the loss, citing spanf 7.459 vs lanczos 7.397. Those are per-method medians over
different images — the exact unpaired statistic this document is about. Paired,
butteraugli favours spanf.

## 3. The README's textures caveat is wrong, and was wrong before the clean corpus

README (2026-07-22): *"textures −1.7 dB / −1.7 ssim2 (SR loses on stochastic
detail)"*, the single loss behind "SPANF wins 7/8 subcorpora".

On the **same 2026-07-22 data**, the paired median is **+8.79** and SR wins.
The −1.70 is the difference of two medians taken over different images; it never
described a per-image loss. The clean-reference re-run puts the paired figure at
+8.13 (win 0.62), so the conclusion survives the corpus change intact.

The plausible story — "SR can't invent stochastic detail" — is exactly why this
went unchallenged for eleven days. It is a reasonable mechanism attached to a
number that does not measure it.

Note `textures`, `renders` and `people` use `__pristine3x` variants in the clean
corpus, so their values are not directly comparable across the two runs: the
reference content is 3× downscaled, not merely re-encoded. The statistic
comparison above is within-run and unaffected.

## Actions

1. **README needs correcting** (awaiting review, per the docs rule): the
   textures caveat is unsupported, and "wins 7/8" understates the result —
   paired, SPANF wins **8/8 on PSNR and butteraugli**, 7/8 on ssim2.
2. Report the paired median and win fraction, not the difference of medians —
   ROADMAP §0.3 already required per-file granularity; this is the same lesson
   arriving through a different door. Report all three metrics paired: on
   `renders` they disagree, and any one of them alone tells a confident and
   incomplete story.
3. `renders` is a metric-disagreement case, not a confirmed regression. Look at
   the outputs before treating it as a model defect.
