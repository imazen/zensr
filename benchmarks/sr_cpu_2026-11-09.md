# Codec-excluded CPU SR measurements — 2026-11-09

The [2048 → 8192 extension](sr_8k_cpu_2026-11-09.md) measures native SPANF
and DSCF CPU latency and peak process RSS with two timed calls each.

The subsequent [DSCF CPU matrix](../docs/research/DSCF_SR_2026-11-09.md#measured-quality-and-cpu-results)
uses the same fixture bytes and CPU placement, with separate matched baseline
blocks. Its measurements are not pooled into this original 12-configuration study.

All **216/216 invocations** completed: 156 in the primary matrix and 60 in
the larger native matrix. This covers 66 model/size/thread configurations
plus six A/A configurations, each with three fresh processes and three timed
calls per process. No pilot samples are pooled into these results.

Intel Core Ultra 7 265K (i265), verified performance-core cpuset, CPU FP32,
batch 1. Latency is the **median of three process means**, in milliseconds.
[Full CSV](sr_cpu_2026-11-09.csv) retains process minimum/maximum/MAD, measured
worker RSS, output throughput and output hashes.

Input tensors are already in memory. No codecs or IQA are timed. Loading,
packing/planning, RNG reseeding and output hashing/destruction are excluded.
Inference, scratch/output allocation, native tiling and required external-model
resize/conditioning/color fix are included. S3Diff retains author PIL
quantization and wavelet color fix. Native returns raw f32; no optional guard
is applied. See the [frozen protocol](sr_cpu_protocol_2026-11-09.md).

## What the measurements establish

Within this original matrix, TSR/tract is fastest at 128→512 with four requested
threads (33.674 ms). At 256→1024, native SPANF is fastest (84.388 ms). These
are distinct trained models; latency does not establish a quality ranking.
The external diffusion CPU references take 14.031–16.607 seconds at 128→512
with four requested threads. Their 256-input cases were not measured.

Native SPANF uses one default tile at input sizes 64 and 128, so requesting
four threads still uses one tile worker. Input 256 supplies four tiles.
The native general/WDN Compact models also retain one tile at 128: their
halo-derived minimum tile size prevents a two-by-two split. This explains
their flat small-input scaling. Existing defaults were measured unchanged.

All configurations use FP32 arithmetic. Native weights are expanded from
retained f16 artifacts before timing; tract uses retained f32 ONNX exports.
The external models use CPU PyTorch references without BF16, INT8 or
torch.compile. ResShift CPU disables the GPU quality study’s FP16 autocast.
These CPU numbers do not measure a future optimized native diffusion backend.

These are descriptive shared-host observations, not a formal Confirm decision
or a promoted production baseline. A/A clone medians differ from native-SPAN
baseline medians by −0.333% to +3.138% across the six cells; that observed range
is not a confidence bound. Only source 7109 supplies the timing fixtures.
No full-resolution diffusion speed or content-wide latency distribution is
established. Model quality evidence remains in the separate
[external SR comparison](external_sr_models_2026-11-09.md).

Every invocation verified finite ×4 output geometry and repeated output
identity. All three fresh-process output hashes agree for each configuration;
all A/A hashes match their native-SPAN baselines. Native tiled paths also
verify exact one-thread output parity. Output equivalence between different
backends is not certified. Across requested thread
counts, all 15 native and 12 tract model/size pairs have identical raw output
hashes, as do the three A/A pairs. All six external PyTorch model/size pairs
have different raw output hashes between one and four threads, despite exact
repeatability within each thread setting. Their difference severity and CPU
perceptual quality were not measured; these CPU references are not a certified
product backend. Model outputs were hashed in memory and discarded; no
restored images or metric maps were written.
